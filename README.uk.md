# AI Radar

## Огляд

AI Radar — адаптивний каталог для пошуку ШІ-продуктів. Він отримує перелік сайтів із публічного FreeSerp API та дає змогу шукати, переглядати категорії, сортувати результати й ділитися станом каталогу через URL.

## Можливості

- Пошук із затримкою 400 мс перед запитом.
- Перегляд категорій FreeSerp і сортування за релевантністю, `went_live`, `first_seen` або рейтингом домену.
- Посторінкове завантаження по 12 результатів, точна загальна кількість від API та обмеження FreeSerp у 10 000 результатів.
- Стан пошуку, категорії, сортування й сторінки в URL, підтримка кнопок «Назад» і «Вперед» браузера.
- Розділ «Нові ШІ-інструменти» для продуктів, доступність яких FreeSerp уперше підтвердив протягом останніх 30 днів.
- Інтерфейс англійською та українською мовами зі збереженням вибору мови в localStorage.
- Кешування TanStack Query, попередні результати під час зміни сторінки, скелетони завантаження, порожні стани та повтор запиту після помилки.
- Адаптивні картки з безпечними зовнішніми посиланнями та запасними значеннями для відсутніх необов’язкових даних.

## API

Проєкт використовує публічний [FreeSerp API](https://freeserp.ai/docs.php) з індексом `sites` і параметром `ai_startups=1`.

За потреби каталог передає такі параметри:

- `q` — пошуковий запит.
- `ai_categories` — категорія.
- `sort` і `order` — поле та напрям сортування.
- `from` і `size` — пагінація. `from` обчислюється як `(page - 1) * size`, стандартний `size` — 12.
- `from_date` разом із `sort=went_live` — для розділу нових продуктів.

FreeSerp повертає точне значення `total` для поточного набору фільтрів. Документоване вікно пагінації обмежене першими 10 000 результатами. `went_live` означає, що FreeSerp уперше підтвердив доступність сайту; це не обов’язково офіційна дата запуску продукту. Саме цей сигнал використовується в розділі «Нові ШІ-інструменти».

Застосунок надсилає запити на `/api/freeserp`. Під час розробки та локального preview цей маршрут проксить Vite. Прямі запити з браузера до FreeSerp блокуються його CORS-відповіддю, тому в production використовується Vercel Function `api/freeserp.ts` як same-origin proxy. Для локального запуску production-збірки `scripts/local-server.js` надає такий самий proxy і статичний сервер (`npm start`).

## Розгортання на Vercel

Імпортуйте репозиторій у Vercel, виберіть Vite як framework preset, команду збірки `npm run build` і каталог результату `dist`. Функція `/api/freeserp` автоматично визначається з `api/freeserp.ts`; змінні середовища та додаткова конфігурація Vercel не потрібні.

## Процес розробки

```bash
npm install
npm run dev
```

Cypress використовує `http://127.0.0.1:5173` як базову адресу. Під час тестів Vite має працювати на стандартному порту в окремому терміналі.

## Production-збірка

```bash
npm run build
npm run preview
```

`npm run preview` локально показує production-збірку. Щоб запустити вбудований Node-сервер із proxy до API, спершу зберіть проєкт, а потім виконайте `npm start`.

## Тестування

Cypress містить п’ять end-to-end тестів у `cypress/e2e/catalog.cy.ts`. Конфігурація розміщена в `cypress.config.ts`, фікстура відповіді FreeSerp — у `cypress/fixtures/sites.json`.

У чотирьох тестах відповіді підміняються через `cy.intercept()` і фікстуру. Вони перевіряють початкове відображення каталогу, пошук і стан URL, пагінацію «Наступна/Попередня» зі зміною URL та перемикання англійської й української мов. П’ятий тест без підміни надсилає запит до реального FreeSerp через Vite proxy, тому потрібен доступ до публічного API.

```bash
npm run cy:open
npm run cy:run
```

`npm run cy:open` відкриває Cypress в інтерактивному режимі. `npm run cy:run` запускає E2E-тести без графічного інтерфейсу.
